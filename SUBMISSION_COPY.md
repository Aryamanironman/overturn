Zetaris integration. Zetaris is OVERTURN's only data path. The seven sources — policy_clauses, denial_reasons, medical_records, eob, procedure_codes, claim_documents, icd10_codes — are registered by scripts/register_zetaris_sources.sql as Lightning file tables; the script also adds two public ICD-10 REST tables and the appeal_evidence and claim_facts views. Agents have one data tool, run_sql, in overturn/zetaris.py. It allows one read-only SELECT/WITH/EXPLAIN statement and rejects writes, DDL and multi-statement SQL; only the Reconciler calls it. SAMPLE_MODE runs the same SQL against data/fixtures/sample.db, a read-only SQLite mirror with the same schema. Verified in this repo: tests/test_zetaris_client.py::test_live_sql_contract checks the POST path, auth headers, UUID X-Request-ID, {"sql","limit"} body and row extraction against a local HTTP double. Live: the seven tables were registered and queried on the cluster over JDBC (13 read-only calls); the USL and five DQ rules pass. Trace: output_examples/live/trace.jsonl.

Meterless engines. Two are implemented. H-MEM provides cross-run memory: overturn/run.py recalls before planning and writes appeal_pattern and insurer_pattern after the packet; overturn/hmem.py uses a local JSON mirror in SAMPLE_MODE and posts to /v1/memories and /v1/memories/recall when HMEM_URL is set. tests/test_hmem.py::test_second_run_recalls_first runs twice; run 2 recalls run 1, including "appeal strength 84" and "Northbridge Health denial pattern". The World Model is the shared ledger: the Reconciler writes 47 evidence lines, the claim and four conflicts; the Critic reads them and writes re-query SQL and actions back. tests/test_world_model.py::test_critic_sees_reconciler_write proves the 47 lines and four findings; tests/test_meterless_adapters.py::test_meterless_adapters_write_case_state_and_recall proves /v1/cases/ava/state. Both adapters are verified against local doubles; in the live run they used their local mirrors. The Nightshift runtime was live. The deterministic router in overturn/router.py is not a Meterless Scout Intent adapter.

Nightshift. overturn/llm.py implements the OpenAI-compatible client: Bearer token, meterless-app, meterless-scope, GET /v1/models, POST /v1/chat/completions and per-agent routing. Every request logs an agent_call with requested_model and the served model; the packet's model_routing records the configured route. Critic and Advocate are pinned to NEMOTRON_MODEL. tests/test_nightshift_client.py::test_nightshift_headers_discovery_and_served_model verifies headers, discovery, selected model and served-model logging against a local double. Live run: Nightshift served 11 agent calls; the trace records nvidia/nemotron-3-ultra-550b-a55b for every call. SAMPLE_MODE labels every agent offline-deterministic; that is the sample packet only.

NVIDIA. NVIDIA contributes only through the Nemotron lane for the Critic and Advocate, the adversarial agents; there is no CUDA, NIM, GPU or NVIDIA SDK code. The pin is in overturn/config.py and overturn/llm.py. The live Nightshift runtime exposed nvidia/nemotron-3-ultra-550b-a55b; it served every agent call in the live run, including the Critic and Advocate.

Unique. The adversarial loop cannot be talked out of evidence-backed findings; rebuttals need at least two source citations; counterfactual source removal recomputes the score (84→65 for policy, records, codes and ICD-10; 0 for EOB); a SHA-256 chain covers 47 evidence lines and tampering breaks it; and DOC-003 stays missing, capping the packet at 84/conditional instead of fabricating a letter. The Zetaris layer is a Unified Semantic Layer: a schemastore container plus usl_claim_review, appeal_evidence and claim_facts, five data-quality rules in dq_claim_integrity, and two verification queries per source. 37 tests pass.
